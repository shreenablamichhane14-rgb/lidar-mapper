# Architecture synthesis: decision record

This is the lead architect's decision record that ARCHITECTURE.md, MODULES.md and ios/Sources/Core/ are written from. Where the three documents disagree with this record, this record wins until they are fixed.

## Verdict

All three judges (CI engineer, product owner, performance engineer) picked **ship-first** (combined totals: ship-first 143, ux-first 137, fidelity-first 116). Base: `docs/design/proposal-ship-first.md` (module map M00 to M38, package layout, capture order of operations, CPU-only rendering and texturing, build plan). Everything below changes or extends it.

## Grafts and fixes (numbered, referenced from the documents as D1, D2, ...)

D1. **ScanEngine contract (from ux-first, fixed).** A non-isolated, class-bound `protocol ScanEngine: AnyObject` with `start()`, `finish()`, `cancel()`, `pause()`, `resume()` and a snapshot callback. Engines do their work on their own serial queue and deliver `LiveScanSnapshot` (a Sendable value type) to the main queue through `DispatchQueue.main.async`. UI owns a `@MainActor final class ScanFlowModel: ObservableObject` facade. Never a `@MainActor` protocol. `FakeScanEngine` (replays a JSON Lines `SnapshotRecording` or a synthetic script) lets UI agents build and demo every scan screen without ARKit; Settings > Diagnostics has a Demo Mode toggle.

D2. **Streaming ZIP.** Backup and restore use a new FileHandle-based `StreamingZip` (STORE, CRC32 in 1 MB blocks, ZIP64 when over 4 GB) in ProjectOps. The in-memory `ZipWriter` from Export stays for small multi-file exports only. Restore unpacks into a staging folder, validates the manifest and SEAL files, then moves into Projects.

D3. **One EditLog.** `edits/editlog.json` holds an ordered `[EditOperation]` plus an undo cursor. Pure functions apply it to CleanModel and to PlanModel, so a wall moved in the plan also moves in 3D Clean. Replaces ship-first's `overrides.json` and `plan.edited.json`. Operations reference our own stable element IDs (`ElementID`), never raw RoomPlan UUIDs directly; `ElementID` carries the RoomPlan identifier as provenance. Re-derivation replays the log; operations whose target disappeared are kept but marked orphaned and listed to the user.

D4. **Object size chooser.** Object mode asks "Small or medium (fits on a table or a chair)" or "Large (appliance, vehicle, equipment)". Small/medium: Apple Object Capture (ship-first 3.4). Large: the LiDAR mesh driver (LiveMeshScreen, no RoomPlan) with a user-tapped seed point, gravity-aligned `OrientedBox.fit(_:gravityAligned: true)`, `SectorCoverage` (8 azimuth sectors plus top) that raises `objectCaptureLeft/Right/Back/Top`, and the crop stored as an edit. Isolation uses MeshProcessing's ObjectIsolation.

D5. **Crash-safe raw capture, no chmod.** In-progress captures write to `Library/Application Support/InProgress/<scanID>/` using append-only JSON Lines (`keyframes.jsonl`, `events.jsonl`, `photos.jsonl`) and binary files. On finish the folder is moved into the package and a `SEAL.json` (file list, sizes, `sealedAt`) is written; opening a project verifies sizes and logs mismatches. Immutability is enforced in code (only `RawScanWriter` writes raw, only while unsealed), never by POSIX permissions. On launch, unsealed InProgress folders offer "Recover unfinished scan". Raw is never modified or thinned afterwards.

D6. **Keep all photos = capture-time gate.** "Keep all photos: Off" means a coarser keyframe gate at capture time. Nothing deletes raw keyframes after texturing. The only removal of raw data is an explicit, confirmed "Free up space" action in ProjectOps (removes superseded scans or original photos of a project, with a warning that Realistic cannot be rebuilt), plus deleting the project.

D7. **FrameCopier.** Inside the ARSession delegate callback, accepted keyframes copy Y/CbCr, depth and confidence into a 4-buffer `CVPixelBufferPool`-backed set, then JPEG encode, Float16 conversion and writes run on the serial "io" queue. If the pool is exhausted the keyframe is skipped and counted. No ARFrame or ARKit-owned pixel buffer leaves the callback.

D8. **Raw mesh anchor-local.** Mesh chunks are stored as delivered: anchor-local positions and normals, indices, per-face classification, plus the anchor transform, anchor identifier and update count (`.mchk` v1 header carries the transform). World space is a derived product. Dirty anchors are flushed every 3 s through the io queue (latest version per anchor, file replaced atomically) and once at room end. A 10 Hz binary pose track (`poses.ptrk`: timestamp, transform, tracking state, thermal state, exposure) is recorded for every ARKit capture.

D9. **House alignment.** Every scan carries a `FrameLink` (`projectFrame` with the session id it shares, `relocalized`, `manual`, `unaligned`). StructureBuilder is only called on rooms whose frame is confirmed shared (same ARSession, or relocalized with tracking normal). After a merge, each room's rigid transform (yaw plus translation) from its capture frame into the structure frame is recovered by matching wall, door and window identifiers kept by the merge (least squares on matched wall endpoints, fallback to the room's own transform if identifiers are kept unchanged) and stored in `derived/structure/alignment.json`. Mesh, keyframes and textures are transformed by it at derivation time. Manual alignment produces the same record, source `.user`, stored as an edit. Rooms from unaligned sessions are never stacked silently.

D10. **Forbidden names.** No top-level type may be named Measurement, Transform, Entity, Scene, Material, Object, Surface, Section, BoundingBox, CapturedRoom, Picker, Label, Image, Text, Color, Path, Shape, Plane (taken by Geometry), Range, Model, View, Anchor, Frame, Camera, Mesh, Project (too generic; use ProjectManifest), Room, Wall, Door, Window. Nested type names must not shadow Swift or SwiftUI names either (no `Range`, `Type`, `Kind` is fine). Names already taken in this target: Geometry (TriangleMesh, AABB3, OrientedBox, Rectangle2D, Plane, Polygon2D, Segment2D, Ray, TriangleQuery, MeshBVH, MeshBVHBuilder, SnapTarget, SnapResult, Snap, SymmetricEigen3), Export (ExportMaterial, ExportMesh, ExportScene, ExportError, ExportText, Plan2D and its members, ByteWriter, CRC32, ZipWriter, OBJWriter, PLYWriter, STLWriter, GLBWriter, USDZWriter, DXFWriter, SVGWriter, PDFPlanWriter), Units (UnitSystem, FractionDenominator, UnitPreferences, LengthFormat, AreaFormat, VolumeFormat, AngleFormat, Tolerance, LengthParser), Support (Copy, GuidanceKind, GuidanceMessage, GuidancePolicy, LogStore, DebugServer, Haptics, DeviceState, SettingsKey), ContentView (SelfTestSuite, SelfTestResult). Reserved by in-flight branches: Coverage (SurfaceClass, CoverageFace, CoverageObservation, CoverageState, CoverageGrid, MissingArea, ScanQualityReport, GuidanceEngine, MeasurementConfidence, ExpectedSurfaces), MeshProcessing (MeshWithAttributes, MeshTopology, EdgeTable, UnionFind), Texturing (every `TX` prefix, TextureBaker, KeyframeSelector).

D11. **Derived stamps.** Every derived product records `DerivedStamp { step, pipelineVersion, inputHash, createdAt }` in `derived/index.json`. A step reruns when its stamp's version or input hash differs. The input hash is computed from the SEAL file sizes of its raw inputs plus the EditLog revision where the step reads edits.

D12. **Wall loop is primary.** Room outline, floor area, perimeter, length and width come from the closed wall loop (wall endpoints from `transform * (+-dimensions.x/2, 0, 0, 1)`, adjacent lines intersected). `floors[0].polygonCorners` is only a cross-check (log mismatch over 5 percent). One shared helper, `RoomOutline`, in RoomModel is used by Coverage expected surfaces, CleanModelBuilder and PlanBuilder.

D13. **Ceiling and floor from mesh.** Ceiling height = median Y of ceiling-classified mesh faces inside the outline minus floor median Y, when at least 25 percent of the outline area is covered by ceiling faces (provenance measured); otherwise RoomPlan's max wall height (estimated). Same for floor elevation.

D14. **Plane detection off** for Room, House, Advanced space and Large object capture. On only in Quick Measure.

D15. **RoomCaptureView with coaching on** (ship-first) in builds 3 to 5. Our banner suppresses tiers 2 and 3 while RoomPlan's instruction is not `.normal`. A headless RoomCaptureSession plus own ARView is a later experiment behind a flag, only if build 3 diagnostics show depth and mesh survive.

D16. **Degraded modes** designed into the UI: `allGood`, `depthStripped` (coverage falls back to mesh-face sampling), `meshStripped` (room switches to the two-pass fallback: RoomPlan pass, then a same-session mesh and photo pass in LiveMeshScreen), `roomPlanFailed` (space scan outputs only). Shown as a one-line note on the quality screen and logged.

D17. **Memory.** In House mode, after each room's final flush, MeshRecord evicts anchors from RAM and keeps id, bounds and file reference only. Log `os_proc_available_memory()` per room; under 800 MB suggest "Finish this floor". Keep ObjectCaptureView mounted between passes (review as an overlay). A manifest flag `reconstructionPending` makes photogrammetry resume on relaunch after a jetsam kill. Every pipeline step declares a memory budget and a reduced variant chosen from `os_proc_available_memory()`.

D18. **Free-space gates.** Refuse a scan below 1.5 GB free, warn below 3 GB. During capture a 10 s watchdog stops keyframes under 1 GB and pauses under 300 MB. Object Capture preflight 3 GB.

D19. **Quality sheet over the live camera** (ux-first): after Done the ARSession keeps running (`stop(pauseARSession: false)`) and the quality screen is a medium-detent sheet over the camera, so Show Missing Areas continues on the same session. The TourHUD shows an arrow to a suggested standable viewpoint 1.5 m in front of the missing area. Windows and mirrors are excluded from missing areas.

D20. **Progressive results.** The result screen opens after the floor plan step; each tab shows a status chip ("Adding color and texture 40%") while later steps run.

D21. **Reference length.** Optional per-room calibration: the user enters one tape-measured distance for a measured segment; a reversible `scaleCorrection` edit operation scales derived measurements (never raw).

D22. **Build 3 diagnostics** (fidelity-first): effective ARConfiguration after didStartWith, `session.delegate === hub` check, anchor and face counts, depth presence, memory, projection round trip under 0.5 px on a live depth pixel, UV checkerboard test for QuickLook and later the viewer, `ObjectCaptureSession` limits, CapturedRoom fixture export.

D23. **DXF.** Export writes AC1009 (R12) without `$INSUNITS` (not an R12 header variable, verify/floorplan-cad.json). Units in millimeters, stated in the file name and a TEXT note. Export module already handles this; ExportUI must not add it.

D24. **Modules merged from in-flight branches replace ship-first originals:**
- Coverage (feat/coverage) = ship-first M13 (grid) + M25 core math + guidance selection + measurement confidence. Ship-first M13 becomes `CoverageLive` (ARKit adapter, sampler, minimap) and M25 becomes `Quality` (adapter from CapturedRoom and CleanModel to Coverage's ExpectedSurfaces, QualitySummary persistence). M14 Guidance becomes `GuidanceUI` (signals adapter from ARKit, RoomPlan and ObjectCapture into Coverage's GuidanceEngine, plus the banner view). M20 MeasureCore uses Coverage's MeasurementConfidence.
- MeshProcessing (feat/meshproc) is used by MeshModel (M22) for merge, weld, island removal, hole fill flagged inferred, simplification for viewer LOD, and by ObjectModel/Large object for isolation and crop.
- Texturing (feat/texturing) replaces ship-first M26's algorithms. M26 becomes `TextureJob`: adapters from raw keyframes, depth and consolidated mesh into `TXMesh`/`TXKeyframe`, a pipeline step calling `TextureBaker`, persistence of atlas pages and UVs. The cell texture stage of ship-first is dropped in favor of the baker at a low texel density (Textured) and a high density (Photo Realistic).

D25. **Build plan re-cut** (priority from docs/tasks/lead.md: build 4 must let an amateur scan a room, see Realistic / 3D Clean / Floor Plan / Raw Mesh, dimensions with confidence, save as a project and export USDZ, OBJ and PDF):
- Build 3 (0.3): Core, Store, CaptureCore, MeshRecord, Keyframes, CoverageLive (minimap), GuidanceUI, RoomCapture, Pipeline, RoomModel, FloorPlan, Quality, MeasureCore, AppShell (Home, mode picker, Diagnostics, Demo Mode), PlanView (view only), Results (QuickLook 3D for clean and raw), QualityUI (sheet), ExportUI (USDZ via RoomPlan, JSON, PDF, SVG, DXF, OBJ raw). Plus the merged Geometry, Export, Units (already on main) and Coverage, MeshProcessing, Texturing when their branches are green.
- Build 4 (0.4): MeshModel, Viewer3D (own RealityKit viewer with Raw Mesh classification colors, Solid, Wireframe, 3D Clean, Textured once TextureJob lands), TextureJob (Textured density), MeasureTool, Results (own viewer, object and wall menus, Hide Furniture), QualityUI Show Missing Areas, LiveMeshView (wireframe), ExportUI (all mesh formats, textured USDZ/OBJ/GLB). This build is the "amateur can do the whole room flow" target.
- Build 5 (0.5): ObjectCapture (small/medium), LargeObject (mesh driver plus sectors), ObjectModel, LiveMeasure (Quick Measure), Structure (house merge plus alignment), HouseUI, PlanEditor (editing through EditLog), CoverageOverlay (live colored mesh).
- Build 6 (0.6): TextureJob Photo Realistic density and exposure normalization, ObjectCrop, ProjectOps (duplicate, archive, backup and restore with StreamingZip, Free up space), Advanced options complete, mesh-refined clean model (optional stage with acceptance tests), SurfaceEvidence for Hide Furniture honesty, reference length, iOS 26 background processing behind `#available(iOS 26, *)`.

D26. **Swift rules for every module.** Swift 5.9 language mode; no macros (no `@Observable`, no `#Preview`); UI models are `@MainActor final class X: ObservableObject` with `@Published`; ARKit, RoomPlan and ObjectCapture delegates are plain `NSObject` subclasses, never `@MainActor`; hop to main with `DispatchQueue.main.async` carrying only value types; every switch over an Apple enum has `@unknown default`; no force unwraps except literals; files under about 450 lines; doc comments on every type and function; UI text only from Copy (new strings in `Support/Copy+<Module>.swift` as `extension Copy { enum <Module> { ... } }`, one file per module); `project.yml`, `MapperApp.swift` and `ContentView.swift` are owned by AppShell (the lead wires self-tests); each module with logic ships `enum <Module>SelfTest { static func run() -> [String] }`.

D27. **Core scope.** Core holds only shared value types, protocols and the package reader/writer skeleton; it imports Foundation and simd only (plus `RoomPlan` in exactly one file, `ObjectCategory+RoomPlan.swift`, for the category mapping). It reuses Geometry (`OrientedBox`, `AABB3`, `Polygon2D`) and Units (`UnitPreferences`) instead of redefining. Core ships `CoreSelfTest` (Codable round trips, binary chunk round trip, EditLog undo and redo, package path layout).
